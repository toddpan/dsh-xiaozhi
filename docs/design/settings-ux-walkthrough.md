# dsh-xiaozhi 设置页逐屏走查 + 端到端语音剧本

> 范围：UX 设计交付（逐屏走查 / 字段级中文文案 / 语音剧本 / 困惑点与修正 / 无障碍与国际化）。**不含实现代码**。
>
> 事实基线（全部来自仓内已存在的两份文档，非新假设）：
> - 连接状态机与重连参数：`docs/architecture-adr.md` §2.6（`disabled → idle → connecting → handshaking → syncing → ready ⇄ degraded → closing → backoff`，401/403 或 close 4401/4403 → `fatal` 且**停止重连**）
> - 配置分层与「为什么改了没生效」：同文件 ADR-005（`deploy` vs `user` vs `env`，`/admin/config` 逐字段返回 `{effective, source, locked}`）
> - 错误码与语音语义：同文件 §2.3（`DSH_XZ_1005 TIMEOUT_PARTIAL` 是 **`isError:false`**；`DSH_XZ_1004 SESSION_BUSY`；`DSH_XZ_1012 CONNECTION_LOST`）
> - 工具目录（grouped=18）：同文件 §2.4
> - 主题令牌与设置页视觉锚点：`dsh-prompt-enhancer/src/client/styles.js` 实测使用的 `--dsw-alias-*` 集合
>
> **这是一份定性模拟，不是统计证据。** 下面的结论是「值得验证的强假设」：它复现的是真实用户在人机交互里会产生的摩擦形状，不代表样本比例。每个判断都可以用 5 位用户的可点击原型走查证伪。

## 0. 免责声明与走查方法

- 走查方式：persona 出声思考（第一人称、口语、不专业）+ 分析师结构化评估（LIFT / Cialdini / Fogg）**分离呈现，不混写**。
- 每屏产出：理性目标 → 情感反应（含挫败点）→ 界面元素清单 → 必须给的可读反馈 → 1–2 条优化建议。
- 五秒测试（Phase 1）不妥协：首屏必须回答「这是什么 / 是给我的吗 / 我该做什么」。
- 走查视口：默认 390×844（手机），另在 1440 宽度复看一遍（设置页在窄屏会换行，字段错位是高频问题）。

Sites seen before: 小智官方控制台的「MCP 接入点」页面（已有一个地址和一串密钥）

PSYCHOLOGY

Name: 阿May | 29F | 全栈工程师 | Google query「dsh xiaozhi mcp plugin」

> **依恋倾向带来的差异（值得记住的规律）**：焦虑型的老陈在「连接中」超过 5 秒就开始怀疑自己；回避型的阿May 对同一段等待几乎无感，但对「看不到生效来源」会立刻失去信任。同一页要同时满足这两种人 → 状态区必须**同时**给情绪安抚（一句话人话）与事实密度（一行等宽小字数字）。

### 0.3 抵达前基线（Phase 0，无界面）

> **老陈（内心）**：插件装好了，说能让我用语音指挥电脑上的 DSH。小智那边的接入点地址我已经复制了，就在控制台那个页面。密钥也有一串。现在要填到 DSH 里……有点怕填错，因为上次填错一个端口折腾了半小时。我就想赶紧看到「连接成功」四个字，别的都不重要。

**相关性契约**：页面必须在最初 3 秒内交付三件事——①「这一步是把 DSH 连到小智」②「要填的两个东西我已经有了」③「下一步动作是哪一个按钮」。任何一屏把这三件事打散到三个折叠区里，这个人就走了。

## 1. 逐屏走查

> 走查以状态为单位（用户感受到的是状态变化，不是滚动位置）。共 10 屏：首次进入、填 URL/token、保存、连接中、已连接、连接失败、重连中、token 失效、运行模式切换、保存失败（校验错误）。
> 每屏末的「分析师评估」使用统一格式：情绪 / trust delta / LIFT / Cialdini / Fogg / CTA 可达 / 技术注意。

### 屏 1 — 首次进入（未配置）

**理性目标**：搞清楚这块设置是干什么的、我手上缺什么、下一步点哪里。

**情感反应**：好奇 → 轻微的「又来了」。看到「小智语音」这个 section 会点进来（因为听说过小智），但一屏里出现「运行模式 / 接入点地址 / 连接密钥 / 工具编织模式」四个陌生词，第一反应是「这些是不是都得填」。
**挫败点**：如果两个空输入框和一个下拉并列、视觉权重相同，老陈会去猜哪个必填，然后挨个试。他复制了地址但不知道密钥在哪 → 会去别的页面乱找，而不是看提示。

> **老陈（出声思考）**：哦，「小智语音」。这就是能让我用音箱指挥电脑的那个吧。……「运行模式」，两个选项，啥意思？「我去连小智」和「小智来连我」——嗯，那肯定是第一个，我要连它。下面「接入点地址」，这个我有；「连接密钥」……密钥在哪来着？控制台那个页面上好像有一串，我找找。下面还有「工具编织」……这又是什么，先不管。有个「保存」，我先点点看？还是先把地址填上。

**界面元素清单**

| 元素 | 说明（沿用现有视觉锚点） |
|---|---|
| Section 标题 | 「小智语音」+ 一行简介（13px/20px，`--dsw-alias-label-tertiary`） |
| 状态条（置顶，横贯整屏） | 圆点 ●（`--dsw-alias-state-warn-primary`）+ 一句话：「还没连接——填好下面两项就能连上」 |
| 三步引导区 | ① 去小智控制台复制接入点地址 ② 把地址和密钥粘到下面 ③ 点「保存并连接」。样式：`--dsw-alias-bg-layer-2` 圆角卡片，12px 行高 18px |
| 运行模式 | 单选（推荐做成两张大一点的单选卡，而非下拉，见 §4.1） |
| 接入点地址 | `type="url"` 输入，placeholder 给真实形状 |
| 连接密钥 | `type="password"` 输入 + 粘贴按钮 + 「显示」切换 |
| 保存并连接 | `--dsw-alias-label-primary` 底、`--dsw-alias-bg-layer-3` 字的 primary 按钮 |
| 折叠区 | 「高级设置（定时保活、并发上限、回复长度）」，默认收起 |

**必须给的可读反馈**
- 顶部常驻状态条：现在到底连没连（不依赖用户往下滚）。
- 两个必填项的「从哪拿」：一句话 + 指向小智控制台。
- 未填写时按钮的语义：禁用 + 一句「填好上面两项即可保存并连接」（不要只说「请填写必填项」）。
- 「高级」区默认收起时，折叠行右侧给摘要（例如「回复长度 1200 字」），避免用户以为里面没东西。

> **ANALYST — 屏 1**
> - Emotional state: `curious`（好奇，略带戒心）
> - Trust delta: `→` 持平。页面没有骗人，但也没有任何「别人也这么配」的证据。
> - LIFT: **Clarity ↓** 为主（四组陌生名词同权重出现），**Anxiety ↓** 次之（不知道密钥从哪拿）。
> - Cialdini active: 无。
> - Cialdini missing: **Authority**（「小智官方接入点」的官方字样/图标能显著降低这一步的心理门槛）；**Social Proof**（本屏不必强塞，但可放一句「已有 N 台设备用这种方式接入」）。
> - Fogg: Motivation `Med` | Ability `Med` | Prompt visible `Yes`（保存按钮可见但禁用）
> - CTA reachable: `Yes`（单屏内可完成，无需滚动——**必须保持这个性质**）
> - Technical notes: 输入框在 iOS 上必须 `type="url"` + `inputMode="url"` 才能唤起带 `/` 的键盘；密钥框必须可粘贴（`autocomplete="off"`，禁用自动纠正）；本屏不要有网络请求，避免首次进入就卡。

**优化建议**
1. **【速赢】把「运行模式」改成两句话的单选卡**：选项文字从 `endpoint / server` 改为「我去连小智（推荐）」与「小智来连我」，后者带一行小字「需要你自己有公网地址」。（LIFT: Relevance ↑，Fogg: Ability ↑）
2. **【速赢】三步引导做成可勾选的清单**：填完地址自动打勾，密钥填完自动打勾，按钮从禁用变为可点。焦虑型 persona 需要「进度可视化」，这比任何文案都有用。（Fogg: Prompt 由 Signal 变 Facilitator）

### 屏 2 — 填 URL 与 token

**理性目标**：确认自己粘的是对的、没有被剪切板弄坏。

**情感反应**：谨慎 → 反复核对。地址很长、带 `wss://` 和路径，老陈会把整串读一遍，然后怀疑「是不是多复制了个空格」。
**挫败点**：
1. **把完整接入地址粘到了「连接密钥」框里**（或反之）——这是最高频的一次性错误，因为小智控制台给的可能就是一整串（含密钥）。
2. 密钥框是密码类型，粘完看不到，无法确认自己没粘错 → 焦虑型 persona 会重复粘贴 3 次。
3. iOS 输入框自动首字母大写 / 自动纠正把地址改坏（`wss://` → `Wss://`），用户完全看不出来。

> **老陈（出声思考）**：先粘地址。……好长一串，`wss://` 开头，后面还有一串斜杠。粘上了。再粘密钥——呃，框里全是圆点，我看不出来粘对没有。算了，点个「显示」看一眼吧，别粘错了。……诶，这个「显示」在哪？找不到。那我粘两遍保险点？……不对，粘两遍就变成两倍长了。算了，直接保存试试。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 接入点地址 输入框 | 单行，等宽字体（`ui-monospace`）以便核对，左侧图标无 |
| 地址解析反馈行 | 12px，输入后即时出现：「✓ 地址格式正确 · 指向 xiaozhi.me」或「✗ 需要以 wss:// 或 https:// 开头」 |
| 连接密钥 输入框 | `type="password"`，右侧两个图标按钮：「显示/隐藏」「粘贴」 |
| 粘贴智能分流 | 若检测到粘贴内容是一整串含密钥的地址 → 自动拆分成两个框并提示「已自动拆成地址和密钥，请核对」 |
| 粘贴后回执 | 「已粘贴 42 位密钥」——不需要露出明文，但**要给出长度与首尾各 4 位** |
| 字段级 hint | 每个框下方一行 12px/18px 小字 |
| 内联校验 | 红字 `--dsw-alias-state-error-primary`，紧贴字段下方（不要只做顶部 toast） |

**必须给的可读反馈**
- **长度与首尾回执**：`已粘贴 42 位 · 首尾 a1b2…f9g0`。这一条直接消灭「粘错没发现」的焦虑，且不泄漏明文（与 ADR-012 的掩码口径一致：只回掩码，永不回明文）。
- 地址格式即时判定（协议、主机可达性不做，只做格式）：先说格式对不对，再在保存时说通不通。
- 剪切板前导/尾随空白与不可见字符的自动清理提示：「已自动去掉首尾空格」。**静默清理比报错好**。
- 「显示」按钮必须有 `aria-label` 与 `aria-pressed`。

> **ANALYST — 屏 2**
> - Emotional state: `anxious`（焦虑，正在自我核对）
> - Trust delta: `↑` 小幅上升——即时格式判定是「有人在看着我填」的信号。
> - LIFT: **Anxiety ↓**（主），**Clarity ↑**（次）
> - Cialdini active: **Commitment**（微承诺：格式校验通过 → 用户更愿意往下走）
> - Cialdini missing: **Authority**（字段 hint 里点名「小智控制台 → MCP 接入点」能建立来源权威）
> - Fogg: Motivation `Med` | Ability `Med→High`（粘贴分流后）| Prompt visible `Yes`
> - CTA reachable: `Yes`
> - Technical notes: 密钥字段禁 `autocorrect/autocapitalize/spellcheck`；粘贴事件要处理 `text/plain` 与多行粘贴（用户常把密钥连同换行一起复制）；显示/隐藏切换后要保留焦点位置，否则键盘收起会导致视口跳动。

**优化建议**
1. **【速赢】粘贴智能分流 + 掩码回执**：一次消除「粘错框」和「看不到」两个高频挫败。预期：用户在这个字段上的平均停留时间明显下降（当前假设是他们会反复粘贴 2–3 次）。（Fogg: Ability ↑）
2. **【重大改进】把「地址」和「密钥」在视觉上绑成一组**：同一个带边框的卡片内两行，卡片标题「① 小智接入点信息」。现在它们与「运行模式」并列，层级是平的。（LIFT: Clarity ↑）

### 屏 3 — 保存（点下按钮到结果出现之间）

**理性目标**：确认「我填的东西被记住了」，并且马上开始连接。

**情感反应**：期待 + 紧张（怕一保存就报错）。按下按钮后如果没有任何变化，会立刻再点一次。
**挫败点**：
1. 按下去没反应（既没有 loading，也没有按钮置灰）→ 重复点击 → 可能触发重复保存/重复重连。
2. 「保存」和「保存并连接」语义不清：用户点「保存」后以为在连了，其实没连。
3. 保存成功只弹一个 2 秒的 toast，用户一低头就错过了，页面其余部分毫无变化。

> **老陈（出声思考）**：点保存。……怎么没动静？再点一下。……哦，它变灰了，原来在转圈。那刚才我是不是点重了？算了不管了。它这就算存上了吗？我要不要刷新一下页面确认……算了先看上面那个状态。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 主按钮三态 | 文案：`保存并连接` → `正在保存…`（带 11px spinner，`prefers-reduced-motion` 下不转）→ `已保存`（`--dsw-alias-state-success-primary` 文字 + 圆点） |
| 按钮位置右侧的常驻回执行 | 12px：`✓ 已保存 · 12:04:31`，**不消失**（toast 会消失，回执不会） |
| 保存中被禁用的字段 | 字段 `disabled`，但**不禁用滚动与复制**（用户要能复制自己的地址去排错） |
| 冲突提示条 | 若某字段被部署配置锁定，保存前就已在字段旁标注（见 §4.3） |
| Toast | 右下角，见 §2.5 文案表；toast 只是补充，**不是唯一反馈** |

**必须给的可读反馈**
- 按钮文案必须从「动作」变「进行中」再变「结果」，三态齐全。
- 保存成功 → **同时**给：toast + 常驻回执行 + 顶部状态条从「还没连接」变为「正在连接」。
- 保存失败 → 就地定位到出错字段（滚动 + 聚焦 + 红框 + 红字），不要只在页面顶部报错。

> **ANALYST — 屏 3**
> - Emotional state: `curious` 转 `confident`（若三态齐全）／`confused`（若只有 toast）
> - Trust delta: `↑`（三态齐全时）；若按下无反应则 `↓↓`（这是最伤信任的一类反馈缺失）
> - LIFT: **Clarity ↑**，**Anxiety ↓**（可逆性：「已保存」意味着可以放心继续调）
> - Cialdini active: **Commitment**（保存是一次明确的承诺动作）
> - Cialdini missing: 无（本屏不需要社交证明）
> - Fogg: Motivation `High` | Ability `High` | Prompt `Yes`（Signal 型：只需提醒）
> - CTA reachable: `Yes`
> - Technical notes: 单次保存只应触发一次重连（与 ADR-008 的幂等口径一致：`requestId / actions` 要幂等）；连点期间必须锁按钮；保存失败时不要清空用户输入（清空 = 用户重填 = 直接流失）。

**优化建议**
1. **【速赢】按钮三态 + 常驻回执行**：toast 会消失这件事在设置页里是纯粹的反馈损失。（Fogg: Prompt 由弱 Signal 变强 Signal）
2. **【速赢】保存失败时滚动并聚焦到出错字段**：`element.focus()` + `aria-live` 播报，键盘与读屏用户都能立刻知道问题在哪。（无障碍刚需，见 §6.1）

### 屏 4 — 连接中

**理性目标**：知道它在努力，并且大概还要等多久。

**情感反应**：期待 → 3 秒后开始不安 → 8 秒后怀疑自己填错 → 15 秒后开始怀疑这个功能根本不能用。
**挫败点**：
1. 静态文案「连接中…」不动，用户无法判断是「在连」还是「卡死了」。
2. 已经有三个内部阶段（connecting → handshaking → syncing），界面却只展示一个词，用户反复刷新页面想「催一下」。
3. 超时（10s 连接 / 15s 握手）后没有可执行的建议，只说「连接失败」。

> **老陈（出声思考）**：连接中……转圈呢，行。……还在转。这都多久了？是不是地址错了？我要不要刷新一下？还是等一下……。哎，它怎么还在转，我电脑上那个 DSH 是不是得开着什么？上面有个「重置」我要不要点？不敢点。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 状态条 | 黄点 ●（`--dsw-alias-state-warn-primary`）+ spinner + 主文案 |
| 阶段文案（一阶段一行，人话） | ① `正在连接小智…` ② `正在打招呼（确认双方版本）…` ③ `正在获取工具清单…` |
| 计时器 | 等宽数字小字：`已等待 4 秒`（`font-variant-numeric: tabular-nums`） |
| 预计上限提示 | 「最多等 15 秒，超时会告诉你原因」 |
| 取消/停止按钮 | 次要按钮「停止尝试」（用户需要一个「我能控制」的出口） |
| 诊断小字 | 12px 等宽：`第 1 次尝试 · wss://…（已隐去密钥）` |

**必须给的可读反馈**
- 三个内部阶段必须映射成三句人话，而不是原地转圈。
- 明确给出**时间预期上限**（10s 连接 / 15s 握手 / 45s 心跳判死），有预期才有耐心。
- 出现「停止尝试」按钮 → 焦虑型人格的控制感来源。
- 计时器不断更新到页面标题（`document.title` 前缀 `连接中…`），用户切到别的标签页再回来能一眼看到结果。

> **ANALYST — 屏 4**
> - Emotional state: `anxious`（等待是最容易流失的状态）
> - Trust delta: `↓` 缓慢下滑（每秒都在流失，除非有阶段推进）
> - LIFT: **Anxiety ↓**（主）、**Clarity ↑**（次：阶段映射）
> - Cialdini active: 无。
> - Cialdini missing: **Authority**（「正在确认双方版本」这类描述暗示了专业流程，能提升耐心）
> - Fogg: Motivation `Med` | Ability `High` | Prompt `Yes`（停止按钮）
> - CTA reachable: `Yes`
> - Technical notes: 阶段文案必须由真实状态机驱动（`connecting / handshaking / syncing`），不要做假进度条；spinner 在 `prefers-reduced-motion: reduce` 下必须静止（用文字「进行中」代替动效）；轮询 `/admin/status` 的间隔建议 1s，且**页面不可见时降频**（`visibilitychange`），避免后台标签页被限流打爆。

**优化建议**
1. **【速赢】阶段化文案 + 计时器**：把「连接中…」变成一个会推进的故事。这是投入产出比最高的一条（LIFT: Anxiety）。
2. **【重大改进】首连自动触发一次「测试连接」并展示握手细节**：例如「对方已回应 · 协议版本已确认」，让用户在等待中获得**具体**的证据，而不是笼统的进度。（Cialdini: Authority）

### 屏 5 — 已连接（工具数 / 最近心跳）

**理性目标**：确认真的通了，并且知道「现在能用语音干什么」。

**情感反应**：释放 → 成就感。这是整页唯一的高点，也是用户决定去试语音的触发点。
**挫败点**：
1. 只显示「已连接」，用户不知道说什么 → 转头就忘了，第二天不会再用。
2. 「最近心跳 12:04:31」这种绝对时间用户读不出「是不是新鲜」。
3. 工具数 `18` 是数字但没有解释，用户不知道多或少的含义。

> **老陈（出声思考）**：绿了！「已连接，18 个工具」。太好了。……那我该说啥？我对着音箱说「小智，我 DSH 上有哪些会话在跑」，它懂吗？……这里要是能直接告诉我一句话就好了。下面有心跳时间，12 点 04 分，刚刚，那就是活的。行，我去试试。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 状态条 | 绿点 ●（`--dsw-alias-state-success-primary`）+ `已连接` + `✓` 图标（**三通道表达**：色 + 形 + 字） |
| 事实行 | 等宽小字：`已发布工具 18 个 · 对方版本 xiaozhi 0.3.1 · 已稳定 6 分 12 秒` |
| 心跳行 | `最近心跳 3 秒前`（相对时间为主，悬浮/点击显示绝对时间） |
| **语音示例区** | 2–3 个可直接照读的例子：「小智，DSH 现在有哪些会话在跑？」「小智，读一下最新那条会话说了什么」+ 每例一个「复制」 |
| 「查看工具清单」 | 次要按钮 → 展开抽屉，按组列出 18 个工具的中文人话名 |
| 工具组开关 | 按组复选框（会话 / 提问 / 文件 / 技能 / 模型 / 系统），每项带一句话解释 |
| 操作行 | `重新连接` · `断开` · `复制接入点地址` |
| 降级提示（条件显示） | `--dsw-alias-state-warn-primary`：「连接有点不稳，仍在工作——短指令没问题」 |

**必须给的可读反馈**
- **相对时间**（`3 秒前`）优先，绝对时间作为补充——这是「活着」的唯一可读信号。
- 把「工具数」翻译成人话：`18 个工具 = 小智现在能做 18 类事`，并可展开看具体清单。
- **必须给「接下来该说什么」**：连接成功是本页的情绪峰值，也是把用户推向语音场景的唯一自然窗口。错过它，用户就再也不会回来。
- 降级态必须明确「还能用」：`degraded` 不是失败，用户看到黄灯会以为不能用了。

> **ANALYST — 屏 5**
> - Emotional state: `reassured`（安心）→ `excited`（若给示例话术）
> - Trust delta: `↑↑`（本页最大一次跃升，务必吃满）
> - LIFT: **Value Proposition ↑↑**（这是全页唯一把「我得到了什么」说清楚的位置）、**Clarity ↑**
> - Cialdini active: **Authority**（版本号、工具数 = 可验证事实）、**Social Proof**（可放「常见用法」）
> - Cialdini missing: **Reciprocity**（语音示例话术就是「先给价值」的免费礼物，必须放出来）
> - Fogg: Motivation `High` | Ability `High` | Prompt `Yes`（示例话术 = Spark 型激励）
> - CTA reachable: `Yes`
> - Technical notes: 心跳行不要每秒重绘整页（只更新该文本节点）；18 个工具的清单抽屉首次展开才拉取；`aria-live="polite"` 播报状态由「连接中」变「已连接」。

**优化建议**
1. **【速赢】加「语音示例话术」区并给复制按钮**：把连接成功这一秒的动机直接转成第一次成功的语音交互。（Fogg: Spark 激励；Cialdini: Reciprocity）
2. **【重大改进】把相对心跳 + 稳定性做成一行「健康度」**：`稳定 6 分钟 · 心跳 3 秒前`，一旦心跳超过 20 秒变黄、超过 45 秒（liveness 判死）变红并自动开始重连。（LIFT: Anxiety ↓）

### 屏 6 — 连接失败（错误原因 + 可执行建议）

**理性目标**：知道到底哪一步错了，以及「我现在该做什么」。

**情感反应**：挫败 + 自责（「是不是我填错了」）→ 如果只看到一句 `WS_HANDSHAKE_FAILED` 或 `ECONNREFUSED`，会直接放弃这个功能。
**挫败点**：
1. 只给错误码 / 英文系统错误。
2. 给了原因但没给动作（「连接失败」四个字是最糟的新闻）。
3. 原因和动作放在两个地方（原因在顶部状态条，建议要往下滚），用户根本不会滚。
4. 没有「把这段信息发给别人求助」的出口 → 老陈会截图发群里，然后没人看得懂那张图。

> **老陈（出声思考）**：红了。「连接失败：ECONNREFUSED」。……这啥意思？我地址错了？密钥错了？还是我电脑上的啥没开？它下面有一行小字「检查地址是否正确」——可我就是复制过来的啊。我该改哪儿？要不我刷新一下页面重来？……（截图发群里）

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 状态条 | 红点 ●（`--dsw-alias-state-error-primary`）+ `连接失败` + `✗` |
| **原因区**（人话一句） | 每个传输层错误都映射一句人话，见下面映射表 |
| **建议区**（紧贴原因下方，1–3 条编号动作） | 每条动作用祈使句，可点击跳转到对应字段或复制内容 |
| 技术详情折叠 | 「技术详情（给懂行的人看）」→ 错误码、时间、尝试次数、已隐去密钥的地址；默认收起 |
| 求助出口 | 「复制诊断信息」（复制已 redact 的文本）+ 「查看运行日志」（跳到日志抽屉） |
| 主行动按钮 | 按错误类型不同：「测试连接」/「重新粘贴密钥」/「重新连接」 |
| 上次成功时间 | 「上次成功连接：今天 11:52」（有过成功 = 说明配置不是全错，能显著降低放弃率） |

**错误 → 人话 → 动作 映射表（必须逐条实现）**

| 内部原因 | 界面人话（一句） | 建议动作（紧邻展示） |
|---|---|---|
| `XZ_2001 WS_HANDSHAKE_FAILED` | 地址能打开，但对面不是小智的接入点 | ① 确认地址复制完整（以 `wss://` 开头）② 回到小智控制台重新复制一次 |
| `XZ_2003 WS_UNAUTHORIZED`（HTTP 401/403） | 密钥不对或已被替换 | ① 重新粘贴密钥（[按钮]）② 若刚在小智控制台点过「重置」，需要用新的那串 |
| `XZ_2005 TLS_ERROR` | 安全连接建立失败（证书问题） | ① 检查设备时间是否正确 ② 若用自签名证书，打开「允许不安全证书（仅自测）」 |
| 连不上主机 / 超时 | 这个地址连不上，可能是打错字，或者你不在同一个网络 | ① 检查地址有没有多余的空格 ② 手机上用小智的那个网络试试 |
| `XZ_2002 WS_PROTOCOL_ERROR` | 连上了，但双方说的不是一套话（版本不匹配） | ① 升级 dsh-xiaozhi 插件到最新版 ② 到日志里看对方版本号 |
| `XZ_2004 RECONNECT_EXHAUSTED` | 连续多次没连上，已放慢重试 | ① 先点「测试连接」看当前是否通 ② 稍等 1 分钟会自动再试 |
| 服务端 5xx | 小智那边暂时有问题，不是你的配置错 | ① 稍后再试 ② 复制诊断信息反馈 |
| 未知 | 连接没成功，原因暂时没识别出来 | ① 点「测试连接」重试一次 ② 复制诊断信息发给开发者 |

**必须给的可读反馈**
- 「原因 + 动作」必须在同一视觉块内，且**不换屏、不折叠**。
- 每条建议必须是**可执行动词**，并尽量带一个可点按钮。
- 「上次成功连接时间」：让用户知道不是全盘皆错。
- 诊断信息一键复制（已 redact，不含密钥明文——与 ADR-012 的 `redact()` 口径一致）。

> **ANALYST — 屏 6**
> - Emotional state: `frustrated`（受挫）→ `curious`（若给可执行动作）
> - Trust delta: `↓`（不可避免）→ 若给动作则部分回升 `↑`
> - LIFT: **Anxiety ↓↓**（这是全页最重要的一屏）、**Clarity ↑**
> - Cialdini active: **Authority**（点名「小智控制台」的具体位置）
> - Cialdini missing: **Social Proof**（「90% 的失败是密钥少复制了一位」这种统计句能立刻降低自责）
> - Fogg: Motivation `Low`（刚失败，动机最低）| Ability `Low`（不知道做什么）| Prompt `Yes`（必须给）
> - CTA reachable: `Yes`
> - Technical notes: 错误码只出现在折叠的「技术详情」里，主界面不出现内部代码；诊断复制内容的生成必须过 `redact()`；不要用 `alert()`/`confirm()`。

**优化建议**
1. **【速赢】错误映射表 + 紧邻动作**：把「ECONNREFUSED」这句话换成「这个地址连不上，可能是打错字」。（LIFT: Anxiety ↓↓）
2. **【速赢】加「上次成功连接时间」与「复制诊断信息」**：前者降低放弃率，后者把求助成本从「截图 + 解释」降到「粘贴」。（Cialdini: Social Proof / Fogg: Ability ↑）

### 屏 7 — 重连中

**理性目标**：知道它自己在努力，不需要我做什么。

**情感反应**：烦躁（「又断了」）→ 无感（如果它自律且不打扰）。
**挫败点**：
1. 重连过程弹 toast 打扰用户，每次重试都跳一下。
2. 不显示「第几次 / 下次什么时候」，用户以为卡死了，去点「重新连接」手动打断退避节奏。
3. 不告诉用户「这期间语音还能用吗」——`degraded` 状态下短查询其实仍可服务。

> **老陈（出声思考）**：又黄了。哦写了「正在重连，第 3 次，8 秒后再试」。行吧，它自己弄，我不管了。……那我刚才对小智说的那句还作数吗？哦下面写了「刚才没答上来的，连上后可以问‘刚才那个怎么样了’」。行，那我等着。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 状态条 | 黄点 + `正在重连（第 N 次）` + `约 8 秒后重试` + spinner |
| 退避可视化 | 一小段横向刻度：`1s → 2s → 4s → 8s → 16s …`（高亮当前档），让「越等越久」这件事变得可预期 |
| 不打扰声明 | 「重试过程不会弹提示，连上后这里会变绿」 |
| 未完成指令的归属说明 | 「断线时正在跑的指令**没有重复提交**；连上后可以让我查一下刚才的结果」 |
| 手动出口 | `立即重试` · `停止重连` |
| 降级说明（若 `degraded`） | 「连接不稳，但简单问题现在还能问」 |

**必须给的可读反馈**
- 次数 + 倒计时 + 退避刻度：三件套，缺一个用户就会手动干预。
- **安静契约**：明确「不会反复弹窗」，否则 toast 轰炸会让用户直接卸载。
- **断线期间的数据承诺**：明确告知「不会重复执行」——这是 ADR-008（幂等 + 不回放）在 UI 上的投影，也是用户最大的隐性恐惧（怕重复跑坏代码）。

> **ANALYST — 屏 7**
> - Emotional state: `bored`（无聊/无感是这里的**理想**状态，不是失败）
> - Trust delta: `→`（安静且诚实 = 不掉信任；反复弹窗则 `↓↓`）
> - LIFT: **Anxiety ↓**（主）、**Distraction ↓**（不要用 toast 抢注意力）
> - Cialdini active: **Commitment**（「不会重复提交」= 对用户资产安全的承诺）
> - Cialdini missing: 无
> - Fogg: Motivation `Low` | Ability `High` | Prompt `Yes`（立即重试）
> - CTA reachable: `Yes`
> - Technical notes: 倒计时用 `nextRetryAt` 计算，不要各自跑一个本地计时器；页面后台时暂停倒计时渲染以省电；状态从 `backoff` 回到 `connecting` 时不要整块重挂组件（避免闪烁）。

**优化建议**
1. **【速赢】把「不会重复提交」写进界面**：这是从架构保证（幂等键 + 不回放）里提炼出的、用户能听懂的安全承诺。（LIFT: Anxiety ↓）
2. **【速赢】明确「安静重连」策略**：`backoff` 阶段不弹 toast，只在状态条更新。（LIFT: Distraction ↓）

### 屏 8 — token 失效（fatal）

**理性目标**：知道「现在唯一要做的事」是什么。

**情感反应**：困惑（「我什么都没改啊」）→ 沮丧（如果被引导去无限点重连）。
**挫败点**：
1. 状态显示「正在重连」但其实已经停止重试（`fatal` 停连）→ 用户白等半小时，这是最坏的一种不诚实。
2. 「密钥失效」但没有「去哪拿新密钥」的指引。
3. 用户不知道自己旧密钥的首尾，无法核对是不是被人改过。

> **老陈（出声思考）**：等等，它写「密钥已失效，已停止重试」？为什么？我昨天还好好的。……哦它下面写了「到小智控制台重新复制一个新密钥，粘到下面这里」。还有我旧密钥的前后几位，`a1b2…f9g0`。行，我去控制台看看是不是我重置过。……不用我瞎点重连了，这个挺好。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 状态条 | 红点 + `密钥已失效` + **`已停止自动重连`**（必须显式说明「停止」这件事） |
| 原因说明 | 「小智平台拒绝了我们的连接（密钥不对或已被替换）。为了安全，我们不会继续尝试。」 |
| 新密钥输入框（就地在同一块内） | `type="password"` + 粘贴 + 显示切换 |
| 旧密钥掩码回显 | `上次使用的密钥：a1b2……f9g0`（不可编辑，只用于核对） |
| 操作 | 主按钮「用新密钥重新连接」；次要「去小智控制台」（外链，带图标提示会跳走） |
| 安全说明 | 「密钥只保存在这台电脑的配置文件里（仅本用户可读），不会出现在日志里。」 |

**必须给的可读反馈**
- 必须**显式**告知已停止重连，并提供唯一解决路径（换密钥）。
- 旧密钥掩码 + 来源标注（`来自：配置文件 / 环境变量 / 部署配置`，对应 ADR-005 的 `source` 与 `locked`）——若来自环境变量，用户改页面是无效的，必须直接说明。
- 一句话安全说明，缓解「密钥会不会被看到」的恐惧（对应 ADR-012 的威胁模型）。

> **ANALYST — 屏 8**
> - Emotional state: `confused` → `reassured`（若指引明确）/ `frustrated`（若无指引）
> - Trust delta: `↓`（事件本身）→ `↑`（诚实告知停止 + 掩码核对 = 透明度换信任）
> - LIFT: **Anxiety ↓↓**、**Clarity ↑↑**（这里最怕模糊）
> - Cialdini active: **Authority**（安全说明 + 明确的技术事实）、**Scarcity**（天然紧迫：不换密钥就用不了）
> - Cialdini missing: 无
> - Fogg: Motivation `High`（想恢复使用）| Ability `Med`（需要去控制台拿新密钥）| Prompt `Yes`

### 屏 9 — 运行模式切换（endpoint ↔ server）

**理性目标**：换一种连接方向，并且明确知道「换完我要做什么」。

**情感反应**：好奇 + 不确定（「两个都能连，那我该选哪个？」）→ 切换后如果什么也没发生，会以为没生效并反复切换。

1. **方向搞反**：用户把该粘到小智平台的地址粘进了设置页（见 §4.1）。
2. 切到 `server` 后出现了「监听路径 / 端口」，用户不知道这地址给谁用、要不要填。
3. 切换后界面上没有任何变化，用户以为失败；实际是需要**重启 DSH** 才生效（ADR-005：`deploy` 类字段由部署层管理；`mode` 也是 `deploy` scope）。

### 屏 10 — 保存失败（校验错误）

**理性目标**：知道哪个字段不对，怎么改对。

**情感反应**：轻微的羞耻 + 急（怕白填）。如果错误提示出现在页面顶部而错误字段在屏幕下方，会加倍烦躁。
**挫败点**：
1. 顶部一条笼统的「保存失败：参数校验不通过」，用户不知道改哪。
2. 字段错误提示在 `blur` 时消失，用户回来改时看不到到底要求什么格式。
3. 页面还在向下滚动时聚焦跳错位置，用户丢失上下文。
4. 已被锁定的字段（`deploy` scope）被用户反复修改 → 每次都「保存失败」，而实际上「保存成功但没生效」。**这两种失败必须区分**，见 §4.3。

> **老陈（出声思考）**：保存失败。哪错了？上面写「参数校验不通过」……我哪知道哪个参数。哦下面那个框变红了，写「地址要以 wss:// 开头」。可我的是 `https://` 啊，小智那个页面给的就是 `https://`。那我该改成 wss 吗？没人告诉我。……算了，我把它删了重新粘一遍。

**界面元素清单**

| 元素 | 说明 |
|---|---|
| 字段级红框 + 红字 | 紧贴该字段下方，12px/18px，`--dsw-alias-state-error-primary`；错误未解决前**不消失** |

| 格式说明（错误时补充） | 出错时把 hint 从灰字升级为「要求」格式说明，例如「需要 `wss://` 或 `https://` 开头，例：`wss://api.xiaozhi.me/mcp/xxx`」 |

**必须给的可读反馈**
- 每个错误：**谁错了 + 要求是什么 + 一个正确例子**。
- 焦点与滚动定位到**第一个**错误字段。
- 读屏播报（`role="alert"` 或 `aria-live="assertive"`，内容为「表单有 1 处需要修改：接入点地址」）。

> **ANALYST — 屏 10**
> - Emotional state: `frustrated` → `confident`（若定位准确）
> - Trust delta: `↓`（失败）→ `↑`（精确 + 例子 = 被尊重的感觉）
> - LIFT: **Clarity ↑↑**、**Anxiety ↓**

> - Fogg: Motivation `Med` | Ability `Low`（不知道改什么）→ 修好后 `High` | Prompt `Yes`
> - CTA reachable: `Yes`
> - Technical notes: 校验在一次 `PATCH /admin/config` 失败后返回的字段级错误必须可映射到 DOM 字段 id；`aria-describedby` 把错误文本绑到输入框；不要用 `title` 属性做错误提示（触屏和读屏都读不到）。

| 立即重试 | `立即重试` | `backoff` 期间显示 |

| 断开 | `断开连接` | 二次确认：`断开后小智就暂时指挥不了这台电脑了。确定吗？` |
| 复制地址 | `复制接入点地址` | 成功：`已复制`（按钮上就地反馈，不用 toast） |
| 复制给小智的地址 | `复制给小智填的地址` | server 模式 |

| 替换密钥 | `用新密钥重新连接` | `fatal` 屏 |
| 诊断 | `复制诊断信息` | `已复制，可以直接发给开发者` |
| 日志 | `查看运行日志` | — |
| 高级 | `高级设置（定时保活、并发上限、回复长度）` | 折叠 |
| 外链 | `去小智控制台 →` | `将在新标签页打开` |

### 2.8 Toast 文案（统一格式：结果 + 一句人话）

| 场景 | Toast |
|---|---|
| 保存成功 | `已保存 · 正在连接小智` |

## 3. 端到端语音剧本（6 个）

> 约定：
> - 工具名与参数取自 `docs/architecture-adr.md` §2.4 的工具目录（18 个 grouped 工具）。
> - 「理想返回文本」是**给 LLM 读的结构化文本**，不是直接播报稿；播报稿由小智自行口语化，但必须遵守「≤2 句 + 不念代码」的约束。
> - 全部剧本遵守 ADR-007 的两段式：`dsh_ask` 只等 `waitMs`（默认 15 秒），超窗返回 `DSH_XZ_1005 TIMEOUT_PARTIAL` 且 `isError:false`。
> - **任何失败分支都不许说「失败」三个字**，除非真的失败了；「还在跑」必须说清楚是「还在跑」。

### 剧本 1 —「小智，我 DSH 上有哪些会话在跑？」

| 项 | 内容 |
|---|---|
| **用户原话** | 「小智，我 DSH 上有哪些会话在跑？」 |
| **意图** | 只读、短查询。要「在跑的」——语义上是「最近活跃/有运行态」的会话，不是全部历史。 |
| **调用** | `dsh_session` `{ action: "list", limit: 5 }`（若返回里带 `runningState`，取 `running`/`working` 的优先） |
| **理想返回文本** | `共 3 个会话最近有活动（按最近使用排序）：\n1. 「重构登录模块」— 正在运行，已跑 12 分 30 秒，最近一条消息 2 分钟前，工作区 ~/work/api\n2. 「修复打包报错」— 空闲，最后活动 40 分钟前\n3. 「写周报」— 空闲，昨天 22:10\n如需详情：可以问我「读一下第一个会话说了什么」。` |
| **小智播报** | 「有三个。第一个叫『重构登录模块』，正在跑，已经跑了十二分钟；另外两个『修复打包报错』和『写周报』都闲着呢。」 |
| **失败分支** | ① 未连接：「我这边跟 DSH 断了，连上我再帮你看——你也可以在电脑上点一下重新连接。」<br>② `DSH_XZ_1013 DEPENDENCY_MISSING`：「DSH 那边有个服务没起来，我现在看不到会话列表，晚点再问我一次。」<br>③ 返回空：「现在一个会话都没有，要不要我帮你新建一个？」 |
| **设计要点** | 播报**必须带名字 + 状态 + 时长**，只念数量等于没说。名字是语音里唯一的锚点，用户会用它做后续指代（「那个重构登录模块」）。 |

### 剧本 2 —「小智，让小智读一下最新会话在说什么」

| 项 | 内容 |
|---|---|
| **用户原话** | 「小智，读一下最新那个会话在说什么。」 |

| **调用** | 两步：① `dsh_session` `{ action: "list", limit: 1 }` 拿到最新会话 `id`；② `dsh_session_history` `{ id, maxMessages: 8 }` |

### 剧本 3 —「让小智重启那个卡住的会话」

| 项 | 内容 |
|---|---|
| **用户原话** | 「小智，那个『重构登录模块』好像卡住了，帮我重启一下。」 |
| **意图** | 破坏性操作（打断当前回合）。ADR-008 规定「同一会话已有 in-flight ask 时第二次 `dsh_ask` 返回 `SESSION_BUSY`」——所以「重启」的正解是 **cancel + 再 ask**，且 must 先确认。 |
| **调用** | ① `dsh_session_stats` `{ id }`（确认是否真的在跑、跑了多久，作为「卡住」的证据）② 口语确认后 `dsh_session_cancel` `{ id }` ③ 视用户要求 `dsh_ask` `{ sessionId: id, prompt: "继续刚才的任务", requestId: "<生成>" }` |
| **理想返回文本** | 步骤①：`会话「重构登录模块」正在运行，已 18 分 42 秒，最后一条事件 6 分钟前（长时间无输出）。判断：可能已停滞。`<br>步骤②：`已发送打断信号。当前回合已取消（状态：cancelled，耗时 18 分 45 秒）。未完成的内容仍保留在会话历史里。` |
| **小智播报** | 确认：「它确实在跑，已经十八分钟没出新动静了。要我打断它吗？」→ 执行后：「打断了。要我在同一个会话里让它接着刚才的活干下去吗？」 |
| **失败分支** | ① `DSH_XZ_1004 SESSION_BUSY`（用户其实是在催）：**绝对不要重复提交**。说：「它还在跑着呢，我没重复发——你要是嫌久，我可以帮你打断它。」<br>② `DSH_XZ_1002 NOT_FOUND`：「没找到叫这个的会话，可能名字我记错了，要我再列一遍吗？」<br>③ 打断失败：`DSH_XZ_1007`：「打断没成功，DSH 那边回了个错——我念给你听：{已脱敏的错误摘要}。要不要去网页上看一眼？」 |
| **设计要点** | **破坏性动作必须有一次口头确认**，且确认语里要带上「证据」（跑了多久、多久没动静），否则用户无法判断该不该打断。**「重启」这个词在语音里等于「取消 + 续跑」，必须在工具描述里向 LLM 说明，避免它去 create 一个新会话**（新会话 = 上下文全丢，这是最坏的结果）。 |

## 4. 最容易困惑 / 出错的 3 个点（附设计修正）

### 4.1 「谁连谁」——把该给对方的东西填到了自己这边

**为什么会错**：设置页里同时存在两类「地址」——「小智的接入点地址」（填到 DSH）和「小智要访问的地址」（由 DSH 生成、填到小智）。两者都是 URL、都在同一屏附近出现，且都叫「地址」。用户在小智控制台复制的地址，很可能就是「让别人连我」的格式，于是出现「地址能打开、但对面不是小智接入点」（`WS_HANDSHAKE_FAILED`）这种极难自诊的失败。

**用户会怎么想**：「我明明复制过来了，怎么还说不对？」

**设计修正**
1. 模式选择改成**方向明确的动词句**做主标题：`我去连小智（推荐）` / `小智来连我`，`endpoint / server` 退到卡内小字。
2. 在 `server` 模式下，把生成的地址放进一个**带箭头的搬运卡**：`把小智填的地址 [复制] →→→ 小智控制台` —— 用视觉方向表达「这是给别人的」。
3. `server` 模式下不给「连接密钥」输入框（那属于另一个方向），并显式写「这个模式不需要密钥；密钥由你在小智那边设置」。
4. 失败时若检测到「填的地址其实是 server 路径格式」，直接说：`你填的这串是「给别人连你」用的地址。如果你是想连小智，请回到小智控制台复制「接入点」那一串。`（这是把错误映射做到极致的价值点）

### 4.2 「还在跑」被当成「失败」——重复下发指令

**为什么会错**：真实 DSH 回合动辄数十秒到数分钟；语音链路必须在 15 秒内给答复，于是返回 `DSH_XZ_1005 TIMEOUT_PARTIAL`（**语义是进行中，不是失败**）。用户听到「没弄完」的直觉反应是「再说一遍」。而在改代码的场景里，重复执行是破坏性的。

**用户会怎么想**：「它好像没听懂，我再说清楚一点。」（于是同一件事跑了两遍）

**设计修正**
1. **话术层**：超窗播报固定三句式——`在跑着` + `我没重复发` + `你待会问「刚才那个怎么样了」`。
2. **工具描述层**（给 LLM 读的约束）：在 `dsh_ask` 与 `dsh_task` 的描述里写明「超时不是失败，不要重发，先用 task 查」（ADR-008 已要求，UI 走查再次确认这是**必须**的）。
3. **界面层**：设置页的「语音等待时间」hint 直接写「任务没跑完它会说『还在处理』，**不会算失败**」；并在页面上提供一个「最近的语音请求」列表（taskId + 状态：进行中 / 已完成 / 已取消），让用户能自己确认「它到底收没收到」。
4. **幂等可视化**：同一 `requestId` 的重复请求，界面上合并为一行并标注「已去重 1 次」，把「我们没有重复执行」这件事变成可见的证据。

### 4.3 配置改了不生效——部署配置层的「沉默否决」

**为什么会错**：`mode / server.path / standalonePort / tools.face` 属于 `deploy` scope，patch 行配置的优先级高于文件（ADR-005）。UI 能改、能保存成功，但生效值不变。用户看到「保存成功」却毫无变化，会开始无意义地反复切换、重启，最后认定插件坏了。

**用户会怎么想**：「我改了五六遍了，它就是不变，这插件是不是坏的？」

**设计修正**
1. **锁定字段一律只读渲染**：左侧一个小锁图标 + 值置灰 + 右侧标注 `由部署配置固定`；悬停/点击给一段解释：「这一项在 DSH 的部署文件里写死了（`cordis.patch.yml`）。要改它需要编辑那个文件并重启 DSH。」
2. **保存结果分两类颜色**：`改不了` = 红（校验错）；`改了但被覆盖` = 黄 + 明确写「已保存到配置文件，但当前生效值来自部署配置」，并给出**生效值 vs 你填的值**的对照行。
3. **设置页顶部给一个「配置来源」折叠区**：逐字段列出 `生效值 / 来源（部署配置 / 配置文件 / 环境变量 / 默认值）/ 可否在页面修改`。这既服务阿May（要事实密度），也保护老陈（不用再猜）。
4. **`explain_config` 的界面化**：/admin/actions 里已有 `explain_config`（ADR 风险 R10 提到），把它直接做成「为什么我改了没生效？」按钮 → 展开决策链（`env > 文件 > patch > 默认`，并高亮最终胜出者）。

## 6. 无障碍与国际化要点

### 6.1 键盘可达与焦点

| 要求 | 具体做法 |
|---|---|
| 全部控件可 Tab 到达 | 禁止 `tabIndex={-1}`（参考插件在会话输入框的按钮上用过 `tabIndex:-1`，设置页**不能**沿用这个习惯——设置页是键盘用户的主战场） |
| 可见焦点环 | 统一 `:focus-visible{outline:2px solid var(--dsw-alias-brand-primary);outline-offset:1px}`（沿用现有锚点）；**不要**用 `outline:none` 且不补替代样式 |
| 焦点顺序 = 视觉顺序 | 状态条 → 模式 → 地址 → 密钥 → 主按钮 → 高级。折叠区展开后焦点不跳走 |
| 校验失败定位 | 保存后 `focus()` 到第一个错误字段，并 `scrollIntoView({block:'center'})`（避免贴边被键盘遮挡） |
| 破坏性操作 | 「断开连接」需焦点落在取消按钮上（安全默认） |
| 快捷键 | 无自定义快捷键需求；但粘贴按钮必须能被键盘触发（`<button>` 而非 `<div onClick>`） |
| 不劫持浏览器快捷键 | 不要监听全局 `keydown` 抢 Esc/Enter |

### 6.2 ARIA 与语义

| 元素 | 要求 |
|---|---|
| Section 容器 | `<section aria-labelledby="xz-title">`；标题用真实 `h2/h3`，不要用 `div` + 加粗 |
| 状态条 | `<div role="status" aria-live="polite" aria-atomic="true">`：连接中→已连接 的切换会被读屏播报，但**不要用 `assertive`**（否则每次心跳更新都打断） |
| 轮询更新 | 只把「状态文本节点」放在 `aria-live` 容器内；秒级计时器放在 `aria-hidden="true"` 的装饰节点，否则读屏会被每秒打断 |
| 错误 | 字段错误用 `aria-describedby` 指向错误文本节点；保存失败的全局摘要用 `role="alert"` |
| 密码框 | 「显示/隐藏」按钮 `aria-pressed` + `aria-label="显示密钥"`；不回显明文时也要有 `aria-describedby` 指向掩码回执 |
| 单选模式卡 | 用真正的 `radiogroup` + `radio`（或 `<fieldset><legend>` + `<input type=radio>`），不要用可点的 `div` |
| 折叠区 | `<button aria-expanded aria-controls>`，展开内容区给 `id` |
| 工具组开关 | 用 `role="switch"` 或原生 checkbox + `<label>` 关联；组标题与说明用 `aria-describedby` 关联 |
| Toast | `role="status"`（成功/信息）与 `role="alert"`（错误），并保证 6 秒内可暂停（`hover`/`focus` 暂停自动消失） |
| 图标 | 纯装饰图标 `aria-hidden="true"`；承担语义的圆点必须同时有文字（色盲用户读不到颜色） |
| 表格/清单 | 日志区用 `<pre>` 但配 `aria-label="运行日志"` 与行数说明 |
| 背景图/渐变 | 本页无装饰性背景，全部用主题令牌实色 |

### 6.3 明暗主题对比度

- **只用 `--dsw-alias-*` 令牌，不写死颜色**。唯一例外是「录制红」这类品牌色（参考插件里出现过 `#e5484d`；若要沿用，必须在两套主题下各测一次）。
- 已知风险点（必须在两套主题下逐项实测）：
  1. `--dsw-alias-label-tertiary` 上的 12px hint 文字：浅色下容易低于 4.5:1 → 12px 属小字，**按 4.5:1 要求**，不足就降级到 `--dsw-alias-label-secondary`。
  2. 状态色文字（`state-warn-primary` / `state-success-primary`）直接做正文色在小字上偏弱 → 建议状态**文字**用 `label-primary`，状态**圆点/图标**用状态色；不要反过来。
  3. `color-mix(..., 6%, transparent)` 这类淡背景（参考插件用过）在两套主题下的对比度不同 → 淡背景只做辅助，不承载文字可读性。
  4. 禁用态：`opacity:.4` 会击穿对比度 → 禁用控件保持 ≥3:1（非文本对比）并同时给 `aria-disabled` 与文字说明。
  5. 焦点环在深色底上的可见性：`--dsw-alias-brand-primary` 在深色主题下必须实测，不够就加 `box-shadow: 0 0 0 2px var(--dsw-alias-bg-layer-3)` 做双环。
- **非文本对比**：输入框边框、开关状态、单选卡选中态都要 ≥3:1（`--dsw-alias-border-l2` 在浅色下通常不够，选中态建议用 `brand-primary` 描边）。
- **不依赖颜色单通道**：所有状态 = 色 + 形（● / ✓ / ✗）+ 字三重表达（屏 5/6/7/8 已按此设计）。
- **动效**：`@media (prefers-reduced-motion: reduce)` 下禁用 spinner 旋转、退避刻度动画、状态切换过渡（沿用参考插件已有的写法）。
- **文字放大到 200%**：字段行必须能从「标签 + 控件」同行换行成上下两行（`flex-wrap:wrap`，`min-width:0`），不得出现横向裁切或控件被挤出视口。

### 6.4 国际化

| 项 | 要求 |
|---|---|
| 文案外置 | 全部文案走 locale 文件（参考约定：`locale/zh.json`、`locale/en.json`，section 用 `locale:'dsh-xiaozhi'`） |
| 键命名 | 按语义而非位置：`modeEndpointTitle` / `modeEndpointHint` / `errAddrScheme` / `toastSaved` / `stateReady` |
| 占位符 | 用 `{n}` `{s}` `{path}` 命名参数，禁止拼接句子（语序不同的语言会崩） |
| 不硬编码单位与格式 | 时长用相对时间函数（`3 秒前` / `3 seconds ago`）；时间戳用 `Intl.DateTimeFormat`；数字用 `Intl.NumberFormat` |
| 长度预算 | 中文文案长度 × 1.6 ≈ 英文长度；按钮与状态条**必须能在英文下不换行**（否则按钮行会掉到第二行、状态条变两行、首屏高度爆炸） |
| 术语一致 | 中文用「接入点 / 密钥 / 会话 / 工具」；英文用 `access point / key / session / tool`，全页统一，与平台控制台保持同款说法 |
| 复数 | 英文下 `1 tool` / `18 tools` 必须走复数规则 |
| RTL | 本插件不承诺支持，但布局需用逻辑属性（`margin-inline-start`）而非 `left/right`，为将来留路 |
| 语言回退 | 缺失键回退中文（沿用参考插件的 `ZH[key] || key` 兜底习惯），但运行时不得显示裸键名 |

## 8. 交付边界与已知不确定

- 本走查基于 ADR 的**规格**而非实现：`degraded` 的实际触发条件（写队列持续满 / 依赖缺失）、平台侧 `tools/call` 真实超时、平台是否支持 `listChanged`，在 ADR 中均标记为**待实测**。这三项若实测结果与假设不符，屏 5/7 的文案与剧本 4 的三句式需要同步修订。
- 「/admin/config 的 `source`/`locked` 逐字段返回」是 ADR-005 的设计要求，UI 走查按此设计；若实现未提供该字段，§4.3 与屏 10 的「两类失败」无法落地，需先补接口。
- 屏 9 中 `both` 模式是否进 UI 取决于 ADR-001 的最终决策（走查按「支持则给第三张卡、默认收起」设计）。
- 所有情感强度与流失位置的判断属于定性模拟，用于生成可检验的假设，不作为度量结论。
